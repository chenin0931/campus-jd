# 岗位分类规则（唯一标准）

适用于所有公司、所有抓取器（含新接入的公司）。各脚本里的旧 classify / classifyMore 已经作废，以本文件为准。

## 1. 取标题头
1. 去掉所有 `【…】` 和 `[…]` 前缀或片段。
2. 按 `-`、`－`、`—`、`–` 切成若干段（去首尾空格），取**第一个含岗位词的段**作为「标题头」；没有任何段含岗位词时取第一段。岗位词：实习、工程师、经理、专员、主管、研究员、分析师、架构师、策划、运营、产品、设计、开发、研发、算法、测试、顾问、管培、培训生、助理、岗、师、Engineer、Manager、Intern。这样「单车业务-数据运营实习生」「供应链-仓储运营」取后段，「招聘实习生 - 产品研发」仍取前段（后段是部门）。

## 2. 排除（技术类）
排除和归类分开：
- **全标题**（任何一段）含 `算法` `工程师` `开发` `测试` 就排除。例：「优才-运控算法工程师-Genie业务部」排除。例外：「开发者」是部门名不算（「市场实习生-开发者AI」保留）；同一段里有「运营」时 `测试` 不算（「测试运营实习生」保留）。
- **只在标题头（岗位名段）**查：`研发` `研究员` `研究型` `研究科学家` `科研` `课题` `技术研究` `数据工程` `网络技术` `数据中心技术` `芯片` `前端` `后端` `客户端` `全栈` `架构师` `运维`，以及英文整词 Engineer / SRE / Developer / Researcher（不区分大小写）。所以「产品经理-研发中心」「运营专员-XX研究院」保留。标题头含「产品」时，`前端` `后端` `客户端` `架构师` `芯片` 不算（「国际化前端产品实习生」「产品解决方案架构师」是产品岗）。单独的「研究」不排除（「AI研究与运营实习生」归运营，「用户研究」归其他）；但任一段以「研究」结尾或含「研究与应用」的课题式标题排除（「混元多模态-视觉智能体强化学习关键技术研究」「多模态世界模型研究与应用-阿里星」），用户研究/产业研究/行业研究/市场研究/数字生态研究除外；标题头里的「产品研发」仍排除。

其他岗位全部保留。`设计` 不再排除。

## 3. 分类（按优先级，命中第一个就停）
| 优先级 | 类别 | 标题头关键词 |
|---|---|---|
| 1 | 运营 | `运营`（先于产品判定：「产品运营」「运营管培生」归运营，与旧口径一致） |
| 2 | AI产品 | 含 `产品`，且含 `AI` / `大模型` / `Agent` / `AIGC` / `智能` / `智算` 之一（AI 和 Agent 不区分大小写） |
| 3 | 产品 | `产品` |
| 3.5 | 职能（前置） | `招聘` `雇主品牌`（先于市场判定：「校园招聘及雇主品牌实习生」归职能） |
| 4 | 商务 | `商务` `BD` `商业化` `渠道` `合作` `招商` `采购` `供应链` `投资` `战略` |
| 5 | 市场 | `市场` `营销` `品牌` `公关` `PR` `广告` `媒介` `增长` |
| 6 | 销售 | `销售` `客户经理` `大客户` `售前` `售后` `客户成功` `KA` |
| 7 | 设计 | `设计` `视觉` `交互` `UI` `UX` `美术` `原画` `动画` `插画` |
| 8 | 职能 | `HR` `人力` `招聘` `HRBP` `财务` `会计` `审计` `税务` `法务` `律师` `合规` `风控` `行政` `秘书` `助理` `内控` `IT支持` |
| 9 | 其他 | 都没命中（如 管培生、策划、编辑、客服、分析师、翻译、校园大使） |

说明：
- 关键词在**标题头**里匹配。英文缩写（BD、PR、KA、UI、UX、HR）不区分大小写，按整词匹配，免得误中别的英文词。
- 「产品运营」按优先级归到 **运营**（运营先于产品判定，与旧口径一致）。
- 管培生没有单独的类别：标题头里有业务词的，按业务词归类（如「运营管培生」归运营，「商务管培生」归商务），只有「管培生」三个字的归其他。
- job_type 不变：`校招` / `实习`。

## 4. 参考实现（JS）
```js
// 全标题排除词：任何一段出现都排除（「优才-运控算法工程师-Genie业务部」）
const EXCLUDE_ANY = /算法|工程师|开发|测试/;
// 岗位段排除词：只在岗位名段里查（「产品经理-研发中心」「运营专员-XX研究院」保留）
const EXCLUDE = /研发|研究员|研究型|研究科学家|科研|课题|技术研究|数据工程|网络技术|数据中心技术|芯片|前端|后端|客户端|全栈|架构师|运维|(^|[^A-Za-z])(Engineer|SRE|Developer|Researcher)([^A-Za-z]|$)/i;
// 岗位名段：标题按「-」切段后，取第一个含岗位词的段（跳过「单车业务-」「供应链-」这类部门前缀）
const ROLE = /实习|工程师|经理|专员|主管|研究员|分析师|架构师|策划|运营|产品|设计|开发|研发|算法|测试|顾问|管培|培训生|助理|岗|师|Engineer|Manager|Intern/i;
const AI = /AI|大模型|Agent|AIGC|智能|智算/i;
const RULES = [
  ['商务', /商务|(^|[^A-Za-z])BD([^A-Za-z]|$)|商业化|渠道|合作|招商|采购|供应链|投资|战略/i],
  ['职能', /招聘|雇主品牌/],
  ['市场', /市场|营销|品牌|公关|(^|[^A-Za-z])PR([^A-Za-z]|$)|广告|媒介|增长/i],
  ['销售', /销售|客户经理|大客户|售前|售后|客户成功|(^|[^A-Za-z])KA([^A-Za-z]|$)/i],
  ['设计', /设计|视觉|交互|(^|[^A-Za-z])(UI|UX)([^A-Za-z]|$)|美术|原画|动画|插画/i],
  ['职能', /(^|[^A-Za-z])HR(BP)?([^A-Za-z]|$)|人力|招聘|财务|会计|审计|税务|法务|律师|合规|风控|行政|秘书|助理|内控|IT支持/i],
];
function classify(title) {
  const segs = String(title).replace(/【[^】]*】|\[[^\]]*\]/g, '').split(/\s*[-－—–]\s*/).map(x => x.trim()).filter(Boolean);
  const h = segs.find(x => ROLE.test(x)) || segs[0] || '';
  // 全标题扫描：逐段查 EXCLUDE_ANY。「开发者」（如「市场实习生-开发者AI」）是部门名不算；含「运营」的段里「测试」不算（「测试运营」）
  const any = segs.some(x => EXCLUDE_ANY.test((x.includes('运营') ? x.replace(/测试/g, '') : x).replace(/开发者/g, '')));
  // 岗位段扫描：含「产品」时端侧词不算（「前端产品」「产品解决方案架构师」）
  const t = h.includes('产品') ? h.replace(/前端|后端|客户端|架构师|芯片/g, '') : h;
  // 任一段以「研究」结尾或含「研究与应用」的课题式标题是科研岗；用户/产业/行业/市场研究除外
  const topic = segs.some(x => /研究$|研究与应用/.test(x) && !/(用户|产业|行业|市场|数字生态)研究/.test(x));
  if (any || topic || EXCLUDE.test(t)) return null;
  if (h.includes('运营')) return '运营';
  if (h.includes('产品')) return AI.test(h) ? 'AI产品' : '产品';
  for (const [c, re] of RULES) if (re.test(h)) return c;
  return '其他';
}
```

## 5. 类别 slug（站点路径用）
AI产品=ai-product，产品=product，运营=ops，商务=business，市场=marketing，销售=sales，设计=design，职能=corporate，其他=other。

## 6. 唯一实现
代码只在 `scripts/lib/common.js` 的 `classify()`，所有抓取器都调它。抓取器可以先做公司特有的标题预处理（如百度去掉（J123）编号、蚂蚁取「蚂蚁集团-业务-岗位」的岗位段、滴滴去掉「27届秋招-」前缀），但不得另写分类规则。

## job_type 规则 (飞书初创公司, 2026-W44 起)
- 校招门户 (recruit_type 为 校招/*): 校招/实习 → 实习; 校招/正式等 → 校招。
- 社招门户: 仅当标题含「实习」或飞书 recruit_type 为 实习 (如 社招/实习) 时保留, job_type=实习; 普通社招 (全职/外包等) 丢弃。
- 无 recruit_type 的岗位: 先请求详情 API, 若详情返回 recruit_type 则按上两条处理; 否则用文本规则 — 标题或详情含「实习」→ 实习; 含「校招」「应届」或届别 (如 26届/27届/2027届) → 校招; 其余丢弃。
- 实现: scripts/reference/fsfetch.py 第6参数 MODE = campus | social_intern | text。
