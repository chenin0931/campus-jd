# 岗位分类规则（唯一标准）

适用于所有公司、所有抓取器（含新接入的公司）。各脚本里的旧 classify / classifyMore 已经作废，以本文件为准。

## 1. 取标题头
1. 去掉所有 `【…】` 和 `[…]` 前缀或片段。
2. 不成对的 `【` `】` `[` `]` 和全角空格当分隔符（「　27届校招】品质培训生」→「27届校招」「品质培训生」）。按 `-`、`－`、`—`、`―`、`–`、`‒` 切成若干段（去首尾空格），取**第一个含岗位词的段**作为「标题头」；没有任何段含岗位词时取第一段。岗位词：实习、工程师、经理、专员、主管、研究员、分析师、架构师、策划、运营、产品、设计、开发、研发、算法、测试、顾问、管培、培训生、助理、岗、师、Engineer、Manager、Intern。这样「单车业务-数据运营实习生」「供应链-仓储运营」取后段，「招聘实习生 - 产品研发」仍取前段（后段是部门）。

## 2. 排除（技术类）
排除和归类分开：
- **全标题**（任何一段）含 `算法` `工程师` `开发` `测试` 就排除。窄例外：岗位段含 `产品` 或 `运营`（含 产品经理）时，全标题扫描只忽略 `算法`，`开发` `工程师` `测试` 照旧排除（「数据产品经理-算法平台方向」「算法产品经理」保留；「产品经理-开发工程师」排除）。例：「优才-运控算法工程师-Genie业务部」排除。例外：「开发者」是部门名不算（「市场实习生-开发者AI」保留）；同一段里有「运营」时 `测试` 不算（「测试运营实习生」保留）。
- **只在标题头（岗位名段）**查：`研发` `研究员` `研究型` `研究科学家` `科研` `课题` `技术研究` `数据工程` `网络技术` `数据中心技术` `芯片` `前端` `后端` `客户端` `全栈` `架构师` `运维` `嵌入式` `机械结构` `结构设计` `电机` `CNC` `关节模组` `技术美术`，以及英文整词 Engineer / SRE / Developer / Researcher / TA（不区分大小写）。所以「产品经理-研发中心」「运营专员-XX研究院」保留。标题头含「产品」时，`前端` `后端` `客户端` `架构师` `芯片` 不算（「国际化前端产品实习生」「产品解决方案架构师」是产品岗）。单独的「研究」不排除（「AI研究与运营实习生」归运营，「用户研究」归分析）；但任一段以「研究」结尾或含「研究与应用」的课题式标题排除（「混元多模态-视觉智能体强化学习关键技术研究」「多模态世界模型研究与应用-阿里星」），用户研究/产业研究/行业研究/市场研究/数字生态研究除外；标题头里的「产品研发」仍排除。

- **制造/工艺**：全标题含 `智造` `制造` `工艺`（含培训生）按工程岗排除；岗位段含 产品/运营 时不算。

其他岗位全部保留。`设计` 不再排除。

## 2.5 英文标题（如 Meshy，不区分大小写，整词）
- 排除（岗位段）：Engineer/Engineering、Developer、Research Scientist、Researcher、Algorithm、ML、QA、SRE、TA。
- 分类：Operations/Ops→运营；AI Product→AI产品；Product Manager/Product→产品；Business Development/Partnership→商务；Marketing/Growth/Community/Content→市场；Sales/Account→销售；Design/Designer/Artist→设计（Product Designer 归设计）；Recruit*/HR/Finance/Legal→职能；Analyst/Analysis→分析。优先级同下表。
- 岗位词另含 Specialist、Associate、Analyst、Designer、Artist、Lead。

| 8.3 | 策划 | `策划`（游戏策划、活动策划；「运营策划」先命中运营） |

说明：
- 关键词在**标题头**里匹配。英文缩写（BD、PR、KA、UI、UX、HR）不区分大小写，按整词匹配，免得误中别的英文词。
- 「产品运营」按优先级归到 **运营**（运营先于产品判定，与旧口径一致）。
- 管培生没有单独的类别：标题头里有业务词的，按业务词归类（如「运营管培生」归运营，「商务管培生」归商务），只有「管培生」三个字的归其他。
- job_type 不变：`校招` / `实习`。

```js
const AI = /AI|大模型|Agent|AIGC|智能|智算/i;
const RULES = [
  // 供应链：在运营/产品之后、商务之前；采购已在前面归职能；「计划」只认业务计划，排除 人才/星/实习/招聘/培养 计划
  ['供应链', /品质|(?<!内容|模型|数据)质量|供应链|物流|仓储|备件|供应管理|质控|质检|(?<!人才|专项|星|实习|招聘|培养|管培|校招|北斗|启航|领航|英才)计划(?!精英|生)/],
  // 模型评测/标注岗归 AI产品（先于审计等职能词）
  ['AI产品', /评测|标注|\bEval\w*/i],
  ['商务', /\bPartnerships?\b|商务|(^|[^A-Za-z])BD([^A-Za-z]|$)|商业化|渠道|合作|招商|拓展|采销|采购|投资|投融资|战略|Business Development/i],
  ['职能', /招聘|雇主品牌/],
  ['市场', /市场|营销|品牌|公关|(^|[^A-Za-z])PR([^A-Za-z]|$)|广告|媒介|增长|Marketing|公共事务|政府事务|政府关系|技术传播|SEO|视频剪辑|视频创意|视频制作|创意制作|新媒体|校园大使|\b(Growth|Community|Content)\b/i],
  ['销售', /销售|客户经理|大客户|售前|售后|客户成功|顾问|规划师|直营管理|新零售|解决方案|\b(Sales|Accounts?|Retail)\b|(^|[^A-Za-z])KA([^A-Za-z]|$)/i],
  ['设计', /\b(Design|Designer|Artist)s?\b|设计|视觉|交互|(^|[^A-Za-z])(UI|UX)([^A-Za-z]|$)|美术|原画|动画|插画|模型师|特效|灯光|用户体验/i],
  ['职能', /(^|[^A-Za-z])HR(BP)?([^A-Za-z]|$)|人力|招聘|财务|会计|审计|税务|法务|律师|合规|风控|行政|秘书|助理|内控|IT支持|财经|资金|理赔|薪酬|组织发展|造价|会务|接待|保密|金融|融租|资管|资产|成本管理|企业文化|组织文化|人才发展|HRIS|企业流程|对外事务|\b(Recruit\w*|Finance|Legal)\b/i],
  ['项目管理', /项目|建设服务|装饰装修|(^|[^A-Za-z])PMO?([^A-Za-z]|$)/i],

];
// LOC/NOTLOC: 城市地名表与 classify.py 中 CN/LOC/NOTLOC 相同
function classify(title) {
  // 先去成对的【】[]，不成对的【】[]、全角空格当分隔符；长横线 — ― 、‒ 也切
  const segs = String(title).replace(/【[^】]*】|\[[^\]]*\]/g, '').replace(/[【】\[\]\u3000]/g, '-').split(/\s*[-－—–―‒]+\s*/).map(x => x.trim()).filter(Boolean);
  const GENERIC = /^(日常|暑期|留用|校招|校园|社招)?(实习(生)?|校招)$/;  // 纯「实习」段不当岗位名，取后面的段
  const h = segs.find(x => ROLE.test(x) && !GENERIC.test(x)) || segs.find(x => !GENERIC.test(x)) || segs[0] || '';
  // 全标题扫描：逐段查 EXCLUDE_ANY。「开发者」（如「市场实习生-开发者AI」）是部门名不算；含「运营」的段里「测试」不算（「测试运营」）
  // 岗位段含 产品/运营 时只忽略「算法」
  const pa = h.includes('产品') || h.includes('运营');
  const any = segs.some(x => { let y = (x.includes('运营') ? x.replace(/测试/g, '') : x).replace(/开发者/g, ''); if (pa) y = y.replace(/算法/g, ''); return EXCLUDE_ANY.test(y); });
  // 岗位段扫描：含「产品」时端侧词不算（「前端产品」「产品解决方案架构师」）
  const t = h.includes('产品') ? h.replace(/前端|后端|客户端|架构师|芯片/g, '') : h;
  // 任一段以「研究」结尾或含「研究与应用」的课题式标题是科研岗；用户/产业/行业/市场研究除外
  const mfg = !pa && (MFG.test(title) || AUTO_TECH.test(title));
  const topic = segs.some(x => /研究$|研究与应用|研究实习/.test(x) && !/(用户|产业|行业|市场|数字生态|评测|政策)研究/.test(x));
  if (any || mfg || topic || EXCLUDE.test(t)) return null;
  if (/运营|Operation|\bOps\b|\bCategory\b|客服|城市经营|\bCSM\b|Customer Success/i.test(h)) return '运营';
  if (h.includes('采购') && !h.includes('产品经理')) return '职能';
  if (/项目经理|项目管理/.test(h)) return '项目管理';  // 显式「项目经理」先于产品；单独「项目」在产品/运营之后（RULES）
  if (/用户研究/.test(h)) return '分析';
  if (/服务储备|储备|NSC|售后服务|服务大区|督导|经纪/.test(h)) return '运营';  // 门店/服务网络岗（服务工程已在排除里）
  if (/设计师|视觉设计|创意设计|\bDesigners?\b/i.test(h)) return '设计';  // 设计师先于产品/市场：AI 产品设计师、营销创意设计师、品牌与视觉设计归设计
  if (/产品营销|产品市场|\bGTM\b/i.test(h) || /^(市场|营销)/.test(h)) return '市场';  // 岗位名以市场/营销开头时不被括号里的渠道等词带去商务  // 产品营销/GTM 是市场岗
  if (title.includes('产品专家')) { const tail = segs.slice(segs.indexOf(h) + 1); if (/城市|门店|零售/.test(title) || tail.some(x => LOC.test(x) && !NOTLOC.test(x) && !ROLE.test(x))) return '销售'; }
  if (h.includes('产品') || (/\bProducts?\b/i.test(h) && !/\bDesigner\b/i.test(h))) return AI.test(h) ? 'AI产品' : '产品';  // 英文：AI Product→AI产品，Product Manager→产品
  for (const [c, re] of RULES) if (re.test(h)) return c;
  // 兜底：落到「其他」的标题若含技术课题词（模型训练/推理/架构/安全/多模态/智能体等），按技术岗排除
  if (TECH_OTHER.test(title)) return null;
  return '其他';
}
```

## 6. 唯一实现
代码只在 `scripts/lib/common.js` 的 `classify()`，所有抓取器都调它。抓取器可以先做公司特有的标题预处理（如百度去掉（J123）编号、蚂蚁取「蚂蚁集团-业务-岗位」的岗位段、滴滴去掉「27届秋招-」前缀），但不得另写分类规则。

## job_type 规则 (飞书初创公司, 2026-W44 起)
- 校招门户 (recruit_type 为 校招/*): 校招/实习 → 实习; 校招/正式等 → 校招。
- 社招门户: 仅当标题含「实习」或飞书 recruit_type 为 实习 (如 社招/实习) 时保留, job_type=实习; 普通社招 (全职/外包等) 丢弃。
- 无 recruit_type 的岗位: 先请求详情 API, 若详情返回 recruit_type 则按上两条处理; 否则用文本规则 — 标题或详情含「实习」→ 实习; 含「校招」「应届」或届别 (如 26届/27届/2027届) → 校招; 其余丢弃。
- 实现: scripts/reference/fsfetch.py 第6参数 MODE = campus | social_intern | text。
